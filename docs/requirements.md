# Cinema Craft 当前需求基线

本文件保留本对话已确认的约束，供后续维护对照。导入运行所需规则全部内置于 Skill，不依赖本文件或私人文档在线可访问。

## 使用与导入

- Lumina 画布 Agent 使用的 Skill；由用户给出一句话或想法，Agent 串联灵感研究、剧本构思、分镜脚本、角色／场景／分镜设计、画面精修、视频与原生后期合成。
- 单文件字符上限现为 **30,000**；按 UTF-16 保守计数，打包上限 **29,600**，保留余量。文件与目录计数仍按最多 50 项保守处理。
- 保留 `SKILL.md / agents / references` 结构；支持的文本格式与合法文件名；专用目录整包替换，避免旧文件叠加。
- 全部 **59 种风格全文**无损保留，风格名称与分类可索引；只按需加载选中风格全部片段。方法与媒介语言可以参考，示例故事、角色、构图和配乐不直接复用。
- 当前发布目标为 `XianlinLu/Cinema-Craft` 的 main；README 保留中英文介绍。既有工具包与无关文件不被覆盖。

## 用户体验与审批

- 新项目从想法先真实搜索情绪版并提炼 5–10 个关键词，原生确认研究方向或真实风格库选择后，按指定编剧方法开发完整剧本。显式时长／区间（如实际要求的 30–45 秒）全流程遵守，未规定才按节奏推导。
- 完整待审剧本必须由 Agent 自动写入真实画布文本／文档节点并读回核对；不能放在 Question 卡片正文、问题或选项中，也不能只发在聊天里。修改先更新画布版本并读回，再发该版本的简短确认卡。
- 所有需要用户判断、确认、自定义修改的节点使用实际 Lumina 原生 Question 卡片。卡片内可点选；修改说明在原生文本／Other 内填写，常规流程不要求在主聊天框多轮输入“继续”。
- 只在关键创意节点和真实不可恢复阻塞等待用户；确认返回后立即执行下一项已授权动作。
- 忽略、超时、预选推荐和生成成功均不等于用户批准。审批绑定真实产物与版本；所有分镜当前版本逐一确认。
- 原生工具、卡片与编辑器调用必须使用当前实际暴露的名称、参数和素材连接；不打印模拟调用，不虚构 API，不替换成外部编辑器。

## 完整生产顺序

0. 自动提取制作简报，真实 Pinterest／可访问图像搜索 → 有来源的 Mood board、可核实互动数据状态和 5–10 个关键词 → 原生“灵感与风格确认”，可选择现有 59 风格库。电影方向按用户给定相关名字加 film aesthetic 搜索；未给名字就用 film aesthetic，并结合实际主题／地域补充检索。不虚构高赞、素材或版权。
1. 按 screenwriting-skills 的影视短片入口，内部完成前提／戏核、人物目标与冲突、结构与场景大纲、对白、完整成稿及诊断改稿，将全部场景、结尾与准确台词保存到画布并读回核对 → 原生卡片仅定位剧本版本并确认决策 → 自动生成有稳定 scene/shot ID 的分镜脚本草案。草案预计时长不冒充实测总表。
2. 剧本确认后 Agent 自动通读该版剧本所有场景、动作与对白，提取／去重全部需明确身份的出镜角色（含无台词、只出现一次及实际非人角色），自行推断未指定的合理外观，自动写提示词并调用原生图像工具逐个生成；不要求用户提供人物清单、上传人物照、建节点或逐人点继续。每个角色一张横向 16:9 优化角色设定图：左 2/5 上下放清晰正脸与严格 90 度左侧脸特写，右 3/5 左右放等比例正／背全身服装视图，仅正面全身图脸部模糊；白底无字，跨视图身份／服饰一致，使用真实参数并核对实际图像。原生“角色三视图”确认名称保留，预览明确展示新排版。人物提示词按排版→已选风格与中性光影→角色背景、五官妆容、服装、体型比例三模块编写；简洁颜值方向按剧本需要选用，不一律神颜，不把真人摄影示例覆盖 59 种已选风格。非人角色按真实解剖适配。后续用清晰脸部视图锁定身份、全身视图锁定服装，不能把模糊脸或多人物排版当视频首帧；既有正确批准资产不因更新重做。同时自动分析必需场景／布景状态并生成真实场景参考，锁定空间、地标／文化细节、光线、轴线和布局；角色与场景／道具区分，纯画外旁白不虚构人物图。首个角色先跑通仅是内部调度；全部所需角色图真实生成并检查后，才展示一次适用的原生角色／场景／道具设计确认，然后推进声音阶段和已就绪的分镜设计。
3. 每个发声角色与独立旁白的声音要求点选 → 实际约 20–30 秒干声试音 → 原生试听确认。无声角色不造假音频，旁白不造假人物图。
4. 依据批准角色／场景／道具和分镜草案生成真实分镜构图／起始状态图，检查人物、手部、物体、空间、文化细节、色光和构图；有问题才实际原生编辑／重生精修，通过则记录检查不额外花费。精修采用最多两次有依据的纠正提交，受理不明先对账，不重置既有重试预算。所有当前图与实测台词共同形成最终镜头生产总表；每镜可见独立列为“场景／镜头 ID、开始时间、结束时间、画面描述、台词、景别、镜头焦段判断、BGM、音效”。保留已有画面描述且不重复新增；起止为全片累计计划时间，连续无重叠、时长为正且总计一致；台词保留角色及原文，景别与镜头／分镜板一致；焦段是有依据的全画幅等效设计建议，二维／正交无镜头时明确不适用，不冒充实测参数；BGM 标注后期独立配乐计划（或无配乐），音效含动作声与环境声及相对镜头的触发时间。声音与素材记录继续保留，镜头总表批准后自动执行。逐字台词、真实音频引用、实测时长、分镜、时间轴与依赖可追溯 → 展示完整总表与所有当前真实分镜图，在原生总表确认一次批准对应表／图版本。

   总表每镜必须有可见具名“画面描述”：写具体主体／人物处境、动作、空间关系、相关感官细节和可见结果，以具体行为与环境互动体现体验；不只写抽象设计建议、功能术语或效果口号。参考图只取表达原则，不复制人物、情节、场景、陈设或示例文本。第一人称表达不自动变成主观镜头、对白或旁白；画面、机位、原台词与声音分清。Agent 在总表确认前自动检查并改写含糊描述，与分镜板、动作时长和连续性对齐，不新增常规问卷，不为措辞修正重做正确素材；实质剧情变化仍走原生批准。
5. 自动生成全部分镜并技术检查；默认 Seedance 2.5、16:9，仅用户明确指定比例才覆盖。Agent 根据剧本／动作判断每镜应有对白、画外音、旁白、音效和环境声；只原生移除模型背景配乐，保留或恢复全部应有声音并检查口型／同步。分镜在用户确认前就必须真实可听；整段静音只能是未完成的中间步骤，不能等最后剪辑再补人声。无对白不等于无音效；仅剧情明确需要的静默段允许无声。
6. 同 scene 且时间、动作、角色、服装、光线、机位连续，前段 QC 就绪且比例一致时，可使用真实视频续写；不同 scene、时间跳跃、动作不连续则独立生成。续写继承源比例并裁去重复前缀。视觉转场硬切。
7. 用户逐段确认所有实际分镜当前版本 → 原生后期方式：仅拼接／仅字幕／两者／Other。
8. 选两者后自动使用 Lumina 原生 Video Editor 完成拼接与字幕；自动根据视频内容、风格、情绪、对白密度和节奏，通过真实原生工具选择或生成原创／已获许可的整片配乐，尊重明确不配乐或指定音乐。原生编辑器保留真实可编辑的视频轨、背景音乐轨、文字字幕轨（选中时）、音效轨以及正确源人声或独立对白／旁白轨，避免重复声。音乐按真实节拍／乐句安排硬切与压低对白下的音量，保留完整人声、音效、动作和停顿。配乐纳入现有最终预览确认，不增加常规问卷。
9. 实际预览 → 原生成片确认或继续修改。修改时在卡片内说明哪段／哪个时间点、哪个点、怎么改；同一编辑器项目局部修改，重新预览并确认，直到明确批准。
10. 只有用户完全确认当前剪辑与混音版本后，才原生导出整个剪辑视频；检查导出媒体包含正确人声、音效、最终配乐、所选字幕且可播放／下载。预览、整齐的轨道、任务提交、第一段视频或散落素材不冒充完成。导出若丢失音轨需技术修复与核对，混音内容改变需重新确认。

## 可靠性与恢复

- 剧本确认后同时自动识别重要道具：重要特写物体、关键剧情／交互物体、重要反复出现的同一物体，以及符合这些条件的背景道具／装饰品。不能只提取人物手持物，也不因在背景或无人触碰就忽略；普通偶然杂物保留场景级处理，不为所有背景物件逐个生图。
- 自动建立稳定道具 ID、剧本依据、各次出场、外观／材质／颜色／关键细节、剧情状态、场景位置／尺度及实际图像版本映射。自动生成对应的清晰道具参考图（默认 16:9），需要时补充有依据的细节／状态视图，不强制套用人物三视图。重复物体复用同一主参考，状态变化不随机改设计；重要背景装饰同时锁定场景中的位置关系。
- 初始角色图与所需道具图全部真实就绪后，在现有配图节点用同一原生卡片确认：仅角色、角色＋道具或仅道具使用适用标题／选项，不增加道具清单问卷或逐物“继续”。无人物仍需生成／确认必要道具；两类均不适用才跳过。总表／分镜规划新发现重要特写物时自动补图，并对新增版本原生增量确认，保留既有角色／声音批准。
- 总表中每个相关出场关联正确道具主图／版本／状态／视图与场景位置，按真实原生端口在各相关分镜和支持的续写任务中引用；只写名字不等于已连接。遵守实际参考数量限制，不整包塞入所有物体，不把道具图接到无此要求的音频输入。修改道具只失效其真正相关的视觉依赖。
- 真实角色—声音—台词—音频映射；试音母版、短声音参考与实际台词音频分开管理。
- 提交前检查素材 ID 类型、内容非空、上传注册就绪、权限／版本／归属；不得向普通 TTS 强行传角色图片或未来音频。默认角色试音逐个自动排队，保留独立成功结果。
- 每次试音、实际台词、配乐、音效执行前，按真实音频操作准备最小必需输入并检查当前保存版本。文本直传或内容注册使用实际支持路径；声线、任务、节点、媒体、内部 content ID 不混用。逻辑人物关联不自动变成音频执行依赖，不提交空的继承引用或未来自身产物。
- `content id is empty` 出现后暂停共享未解决输入配置的后续未提交任务，避免逐个角色重复弹错；仅在观测到输入修复且受理状态明确后有限重试，成功后自动恢复队列，不反复要求继续。角色图和独立成功产物保留。后台内部 ID 对外不可修复时如实报告，Skill 不能关闭／阻止平台原生错误弹窗。
- `content id is empty` 与参数、临时失败、版权／内容拦截分别处理；有实际技术修复才有限重试，同一任务重复通知不重复生成。未知内部原因不能编造。
- 画布提交前同步失败单独处理：节点准备、生成任务受理、真实媒体产物分开记账。先完成第一个真实所需角色，再串行推进其余角色；同一画布写操作串行，保留已有空节点、已受理任务和正确产物，不重复造节点或付费任务。
- 同步错误先读取真实工具返回／节点／任务／产物；最多三次额外非生成对账恢复，遵守真实宿主等待／调度，不增加原有最多两次已确认临时提交失败的生成重试。仅权威确认未受理、输入就绪且同步恢复时可提交原节点；受理不明不能盲重提，已成功产物只需真实原生绑定恢复。
- 工具调用 Completed、8/8 待办、空图片框不等于生成成功。临时错误不额外问继续；持续宿主故障保存明确断点，使用真实原生异常卡片。缺少调度不承诺稍后自醒，不能跳过全局同步屏障或删除无关画布历史来绕过。
- 当前模型音频单条、数量、合计时长和续写画幅按真实运行约束检查。不能用整段多人试音塞满单次视频请求。
- 平台内容拦截停止盲目重试；真实原创素材修改需原生确认，或平台复核。不能通过变声、隐藏名称、换接口、提取被拦结果来规避。
- 保存阶段、批准版本、真实素材与任务、原始／去配乐分镜、续写依赖、原生编辑器草稿与版本、字幕、配乐节拍、最终导出及下一动作。中断后先对账再继续，避免重复付费提交。
- 技术 QC 与用户批准区分；总表已批准时，同场景后续段可消费 QC_READY 前段，无需提前等待稍后的逐段用户确认。后期前仍需全部当前分镜批准。
- 批准的生产表与后期编辑映射分别版本化；只重做受影响依赖，保留正确角色、声音、分镜和人工作业。字幕根据实际剪辑时间轴更新。
- 必须依赖真实原生工具与后台续跑能力；Skill 文本不能安装缺失功能、保证平台审核或自行唤醒。验证不到的能力或结果如实标注，不虚报全自动实测完成。

## v6 研究与编剧边界

- 两个自包含运行参考 story-development.md 和 moodboard-visuals.md 承接编剧与研究／设计方法。新增方法来自用户指定编剧仓库的影视核心与短片路径；不是安装全部 26 个模块或复制其书籍引文／剧本案例。来源及许可保留在独立说明和包内。
- 搜索图与生成生产资产分开；互动数只有实际可核实时才用于高赞筛选。Pinterest 不可访问时诚实标注其他公开检索来源，无法查看任何图时走原生恢复／风格库，不伪造搜索。
- 风格库路线读取选中完整规范；研究路线锁定可执行视觉方向，不伪造库 slug，不把真人需求强行换卡通。所有决策仍走原生卡片，实际确认后自动继续。
- 目标时长包含片头、片尾、CTA 与停顿，试音母版不算入成片。后期再次检查实际成片区间，不能为了卡点截台词或突破上限。
