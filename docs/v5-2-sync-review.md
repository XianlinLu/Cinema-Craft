# v5.2 画布同步与任务提交恢复

## 截图能够说明什么

2026-10-23 的反馈图显示多个三视图节点仍为空，工具卡片 Completed、任务计数 8/8；Agent 的文字说明称提交前同步连续两次失败，未提交新任务。截图没有展开 Canvas 原始返回、任务 ID 或错误码，因此不能证明其隐藏原因，也不能把 Agent 的转述当作权威未受理证据。

应当区分：画布节点已创建、输入已保存、平台已受理生成任务、真实图片已返回、用户已批准。截图支持“尚未看到真实图片”，不足以推断是提示词、版权、额度、并发、网络或其他内部服务问题。本次改动处理编排和恢复行为，不能直接修复 Lumina 的服务端同步故障。

## Skill 的针对性调整

- **先跑通第一份真实所需产物。** 剧本批准后优先复用已有角色节点，核对实际输入；第一个角色提交并观察真实结果后，再默认串行自动推进其余队列。没有额外付费测试图，也不等待每张图的人为“继续”。
- **分清准备／受理／产物。** 空节点、一次 Canvas 调用成功、工具清单计数均不代表生成阶段完成。进度分开记录，不再用节点创建完成冒充角色图完成。
- **先对账再恢复。** 对照真实工具返回、节点、任务和媒体；已受理的跟踪原任务，已生成但画布展示过时的修复原生绑定，权威未受理的在同步健康后提交原节点。受理不明不盲重试，也不因未返回 ID 就认定没有任务。
- **同步恢复与生成重试分开。** 一次恢复事件最多三次额外非生成读取／对账，遵守实际 Retry-After、宿主等待与调度。原有最多两次确认临时提交失败后的生成重试不扩大，不跨回合或换节点重置预算。
- **共享画布顺序写入。** 读取当前版本，按真实工具能力保存／连接／执行，不并发写旧版本。不删除已有批次、历史或无关媒体，不绕过真实全局同步屏障。
- **真实恢复能力。** 可恢复时立即继续；持续失败则保留原节点、原批准与精确断点，使用原生异常选项。没有实际宿主调度时，不承诺稍后自动恢复；卡片或云端保存本身也失败时如实说明，不模拟卡片。

## 对现有卡住项目的处理

加载新版 Skill 后先进入同一画布，检查已有角色节点和所有已受理任务，不重新创建整批节点。若原始工具返回确认该批未受理且同步恢复，就从第一个未生成节点继续；若发现已受理／已生成任务，则跟踪／复用；状态不明先核查，不重复付费提交。更新文件本身不会自动唤醒已经结束且未调度续跑的旧会话。

若仍阻塞，需要展开失败的 Canvas 工具记录，保留原始错误文本、请求／日志／任务 ID 以及同步是否影响只读查询，以便判断是否为可修复绑定、持续服务异常或其他问题。本文不虚构内部刷新 API，也不承诺文本规则能消除服务故障。
