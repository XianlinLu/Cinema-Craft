# v5.4 音频空内容 ID：提交前准备、故障队列暂停与自动修复

## 这次截图与已知边界

2026-10-23 的弹窗再次显示 BALLMAudio 的 `GenInputsFromPipeline ... validate audit content 0: content id is empty`，截图中 code 为 15000。这与此前音频输入校验空 ID 属同一错误类型，但不证明两次缺的是同一项、同一节点或同一后台原因。它不是图片／视频版权拦截的证据，也不能仅凭 content 0 就确定缺角色图、台词、声线或参考音频。嵌套请求 ID／时间差不自动证明缓存过期。

v5.3 已有错误后的通用处理；v5.4 将详细输入协议集中到 `references/speech-inputs.md`，由入口、角色声音、执行循环和生产流程在每次音频执行前明确读取。它仍是给 Agent 的行为指令，不是平台内部的错误拦截程序。

## 具体改动

1. **明确操作。** 区分真实的已有声线 TTS、原创声音设计、参考音频处理、配乐与音效。只传当前操作真正需要的输入，保持用户选定声音；角色图关联不默认成为音频执行输入，首段试音不依赖未来自身输出。
2. **准备真实输入。** 使用实际支持的文本直传或内容注册；检查非空文本、真实素材类型、生产任务、上传注册、访问／归属／版本及保存配置。节点、任务、媒体、声线、URL 与内部内容 ID 不混用；空的继承可选项只有在诊断后通过真实能力修复／移除，不无故断开有效参考。
3. **实际就绪才提交。** 能读取时检查保存后的节点；有真实非生成校验能力才使用，不虚构接口。隐藏的内部编译结果不可声称已检查。默认逐个真实试音自动运行，不额外产生付费测试片段。
4. **自动修复而非原样重试。** 根据可见证据修复缺文字、未完成注册、错误绑定或空可选项；核对变更和既有任务受理后才有限重试，保持原有最多两次不同技术修正上限。不因换节点、延迟或改名字重置预算，不重做批准角色图。
5. **暂停共享故障配置。** 首个未解决错误会暂停同一输入路径的后续未提交角色，避免每个节点重复弹窗。独立就绪工作和已受理任务继续对账；修复后的真实任务成功再恢复队列。
6. **保留原生体验。** 技术修复成功直接继续，不加常规问卷；只有真实无法恢复的阻塞才使用原生恢复卡片。缺内部修复能力时保留错误、请求与节点记录供平台排查，不编造成功或无限重试。

## 对弹窗的实际作用

降低空引用提交和同批重复执行，有助于减少可预防的失败。平台可能在工具错误返回 Agent 前就弹出首个窗口；Skill 无法禁止、拦截或保证自动关闭它。没有真实支持时不添加 `silent` 等虚构参数，也不靠隐藏／关闭弹窗冒充修复。若外部字段全部有效而内部仍返回空 ID，需结合真实失败节点的输入及工具日志排查。
