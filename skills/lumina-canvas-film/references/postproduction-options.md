# Post-production options and subtitle-free delivery

Apply `language-policy.md` to every authored card field and artifact. Read this reference after all current shots are approved and before constructing the post-production card, and when changing subtitle scope in an existing editor draft. Native editing itself follows `production-workflow.md`; soundtrack handling follows `audio-postproduction.md`.

## Post-production choice contract

After every required current shot has real user approval, present ONE native Post-production Options card in the project language. Author only the three business choices below; Other is a host/custom-input route, not another editing mode. Do not show legacy Stitch only alongside Generate without subtitles, because the new choice replaces that legacy no-new-subtitle assembly route with an explicit subtitle-free result.

| Authored English option | Scope after an actual response |
|---|---|
| Generate without subtitles | Automatically assemble/edit approved shots in the SAME native Video Editor project, prepare final scoring unless excluded, omit dialogue/narration subtitles and deliver ONE finished film after final review/export. Preserve speech, effects, ambience, timing, ratio and hard cuts. |
| Subtitles only | Add editable timed subtitles to the approved existing timeline, or caption separate approved clips without unrequested stitching. Preserve the existing approved picture assembly. |
| Stitch + subtitles (recommended) | Automatically assemble/edit approved shots and add editable timed dialogue/narration subtitles in native Video Editor, then final review/export. A recommendation is not approval. |

### Construct exactly one custom-input route

Inspect the ACTUAL native Question schema/behavior before dispatch. If it automatically supplies Other or a free-text alternative, send ONLY the three authored business options; never add Other, other, Custom, a translated equivalent or a second custom option manually. Reuse the host's native text entry for custom scope and later modification details. If Other is an exposed optional native feature, use that feature once rather than adding an option that duplicates it. If no built-in custom route exists, use one actually supported native custom-text route only; invent no schema fields or fake text box. Respect the real option limit, including any host-added row. Use native paging only if that limit prevents exposing the actual choices together; never silently drop a mode or simulate a card.

Before dispatch, inspect the authored options AND known host-added options. Exactly three distinct business choices and at most one custom route should be available, with no case/translation/synonym duplicates. This check applies to every decision card, not just post-production. An older pending card must be reconciled/replaced through real supported operations without leaving two active versions; do not recreate an already answered card. Save the actual returned value and the resolved scope, not an assumed array position or translated label. An empty or ignored custom response remains pending.

### Execute and verify the no-subtitle choice

Generate without subtitles is an editing/export choice, NOT a new generation model, silent output, no-post-production mode or a workaround for a missing editor. It authorizes assembly and subtitle removal on this delivery revision. Do not regenerate already approved shots/voices or ask for another routine continue. In an existing draft, remove/disable only the relevant dialogue/narration subtitle clips/tracks using actual native controls; preserve approved title/end-card/required in-scene text and unrelated human edits. Do not delete all text tracks to remove captions. Burned-in subtitles cannot be removed by hiding an editable track: prefer the actual clean approved source or a genuinely supported correction route; if none exists, report the precise native recovery blocker rather than claim they disappeared. Preserve all intended audio and never confuse no subtitles with no dialogue or no music.

Persist the chosen scope and actual caption state with the editor revision. When a user changes from both/subtitles to no subtitles, revise the SAME editor project, invalidate only the affected final-preview/export approval, verify the current picture/audio/text and ask Final Edit Review for that new revision. Do not reopen unchanged script, character, voice or shot approvals. A prior final approval cannot authorize an export after caption removal. Check the actual final preview and exported video for unintended subtitles, complete sound and one-film delivery; a saved flag or hidden track alone is not proof.

If native editor/timeline/export capability is unavailable, preserve the project and use bounded native capability recovery. Generate without subtitles still requires the real editor for a stitched film. Delivering separate approved clips requires a genuinely explicit different user scope through the single native custom route; never silently downgrade a request for one film. No screenshot message or unverified tool name establishes what capabilities this session exposes.
