# Durable production, native reviews and Video Editor

## Priority and actual capabilities

The latest sequence governs: idea/brief → real Mood board + 5–10 keywords → native direction/library choice → staged screenplay development/revision and script approval → provisional shot script → real character/scene/prop design and refinement + combined visual approval → voices/auditions + real shot-board design/refinement → measured final table AND board approval → all shots → EVERY shot approved → native post choice/editor → final review/revision → verified export/download. Read `story-development.md` and `moodboard-visuals.md` for these new stages; older script-first/optional-board shortcuts no longer govern. Earlier unconditional assembly cannot bypass these gates. Preserve style grammar, exact speech and runtime-control.md's execution loop plus production-requests.md, characters-voices.md and props-assets.md's visual/audio rules.

Discover real native canvas schemas: canvas text/document create/update/read, Question, images, speech/voices, video, task status/continuation, and Video Editor project/media/timeline/caption/preview/export/download operations. The screenshot establishes UI labels, not callable names or parameters. Save the actual bindings and supported ports. Use only the host's native nodes and supported connections; a fake node, printed JSON, editor description, HTML project, external editor or ffmpeg result is not a native Video Editor operation. Do not install/run OpenFilm or redirect this workflow to its Studio. If a required tool is missing, report its precise limitation through native recovery and retain state; a Skill cannot register tools. If Question itself is missing, state the blocker before new paid work rather than imitate a card.

## Video defaults, BGM cleanup and scene boundaries

Use **Seedance 2.5** for video by default; bind its actual native model/schema and use native recovery if unavailable rather than silently substituting. Film ratio is **16:9** unless the user explicitly requests another ratio; platforms, genres, devices and reference images are not overrides. Apply project ratio to boards, independent clips, editor and exports; character sheets remain 16:9. Extension inherits its source ratio: omit/adapt the API field as required instead of forcing a conflicting fixed ratio.

Store scene_id, shot_id, continuity reason, mode and predecessor/version in the table. True extension is eligible only for consecutive action in the SAME scene/time with compatible identity, costume, light, space and camera, a ready QC-passed BGM-free source at project ratio, and actual native extension support. A shared location/reference port is insufficient. Different scenes, time jumps or broken action are independent; never carry the prior scene's video/last frame as continuation. Bind only the intended predecessor and approved identity assets. Trim returned source prefixes to avoid duplicate footage and record actual in/out/duration. Revisions invalidate only affected dependents.

Apply `audio-postproduction.md` before sound planning, cleanup and every shot's audible QC. Remove ONLY MODEL-GENERATED BGM from successful shots BEFORE user review, final editing or continuation reuse. Preserve dialogue, off-screen speech, narration, required effects and ambience. Request no generated music using actual supported controls; a prompt alone proves nothing, and a global audio-off switch is not BGM-only removal. If source sound already contains no BGM, keep it. A soundless source passes only when the approved plan genuinely calls for silence; otherwise it needs real sound composition before review. Use native separation or a true music stem where available. If a successful mixed source must be muted as an intermediate reconstruction, restore ALL required voices/effects/ambience, timing and visible lip-sync within that same preparation job. A silent video plus detached audio or a promise to add sound at final editing cannot pass QC_READY. Missing cleanup/composition capability blocks that shot through native recovery. This normalization does not authorize stitching/subtitles early. Never extract or process rejected/blocked outputs to evade moderation.

Keep raw asset provenance plus actual prepared-clip ID/version, cleanup method, native task IDs, retained/restored audio roles, measured ratio/duration and check status. Inspect the prepared playable clip; use that ready version for approval, editor import and extension, not a stale raw BGM-bearing asset. Later planned/approved whole-film music is a separate editor track, following beat-aware cuts; do not restore random model BGM.

All visual shot/scene boundaries use **hard cuts**: no automatic dissolve, crossfade, wipe, morph, bridge transition or transition overlap. Same-scene continuation has no artificial transition. Keep contiguous picture boundaries, complete speech and essential action. Audio-only music fades/ducking do not create visual crossfades.

## Master-table column contract

Before native **镜头生产总表确认**, save/read back EVERY shot on canvas (runtime-control.md), using these headers: **场景／镜头 ID | 开始时间 | 结束时间 | 画面描述 | 台词 | 景别 | 镜头焦段判断 | BGM | 音效**. The existing concrete 画面描述 remains a single column using production-requests.md's current writing standard; no duplicate description or new questionnaire. Keep technical details linked by stable scene/shot ID so readable creative columns do not remove the actual asset/dependency/status ledger.

- **开始时间 / 结束时间:** absolute positions in the approved production plan, starting at 00:00:00. Use one consistent HH:MM:SS format (or HH:MM:SS.mmm when real subsecond precision is needed); distinguish these from local shot cues starting at 0. End is exclusive, duration = end − start > 0, and each shot begins at the preceding end across scene boundaries. Derive boundaries cumulatively after measured speech/action allocation; follow the existing integer prompt-timing rules. Show total runtime. No overlap for hard cuts, independently rounded gaps, or resetting the film clock for each scene. Label planned times as planned; actual generated duration/source in/out and later editor time are separate measured/versioned records. Post-production trims update the edit map rather than silently rewriting an approved production table.
- **台词:** exact approved wording with speaker/line identity and an explicit 对白、画外音 or 旁白 label as applicable. No spoken content is **无台词**, not an invented line. Keep off-screen/narrator ownership and per-shot speaker rules; show exact line-span mapping when splitting speech, and retain real approved audio IDs/durations in shot detail. Sound effects and BGM are not dialogue.
- **景别:** choose the framing needed by the action/story, e.g. 大远景、远景、全景、中景、近景、特写 or 大特写. Name what is framed when useful; do not confuse shot size with lens length, camera movement or subject size. A genuine within-shot framing change states start → end and must agree with the planned camera path. Do not introduce contradictory setups merely to fill this cell.
- **镜头焦段判断:** provide an intentional lens proposal plus a brief reason tied to subject distance, spatial relationship and the selected style. For physical/virtual perspective cameras, label a chosen value or justified range in **35 mm full-frame-equivalent mm**, e.g. a wider spatial view versus a compressed detail; do not claim a value was measured or guaranteed by a generative model. Shot size alone does not determine focal length: reconcile position/distance, framing, perspective and board. Avoid switching focal length merely for variety or contradicting continuous extension. For flat/orthographic graphics without a perspective lens, explicitly write **不适用（二维／正交；说明构图尺度）** rather than fabricate optical metadata. Send only real supported parameters; a lens direction in prompt text is not an unexposed API argument or proof of optical execution.
- **BGM:** write **后期独立配乐：…** with the story/style function, mood, instrumentation/texture, intended cue range, entry/exit and continuity/ducking as relevant; or **无配乐** for an explicit no-score choice or intentional scored silence. A shared scene/whole-film cue keeps one stable cue ID across relevant shots, not a new unrelated song per row. Before real score creation, mark planned/pending music and beat positions honestly; do not invent an asset ID, BPM or analyzed beat grid. Exact musical markers follow actual selected/generated audio later. This column is a FINAL native-editor scoring plan, never an instruction to generate model BGM inside each shot. Respect user music choices and original/cleared sources; final selection and mix appear in the existing final preview approval.
- **音效:** specify required action-synchronous effects and ambience with their source/event, local cue or interval, continuity and rough level/placement when relevant; distinguish designed/planned cues from real prepared media. Use **无音效／有意静默** only when supported by the scene; no dialogue does not imply no ambience. Effects/ambience and intended human speech must remain audible in the prepared shot before review, even though BGM is deferred. Real effect IDs/versions and native editor track placement stay traceable in shot detail. Do not assume or claim stems/separation or sounds not actually produced.

Automatically check all rows before presenting the existing native approval: all required visible columns populated; single description; exact speech fits measured time; contiguous positive project intervals and correct total; shot size/lens/camera/board consistent; BGM stays deferred; effects and speech have an actual viable production route. Repair only deficient planning fields without restarting correct assets or asking routine lens/music questionnaires. Substantive changes to approved story, voice, visuals or explicit user choices use the relevant existing native revision gate. Carry approved framing/lens intent and sound cues into boards, native requests and the editor cue map; verify actual output rather than infer success from the table.

## Native Video Editor: adapted editing method

Method reference: OpenFilm's SKILL.md and packages/openfilm/MANUAL.md, revision cf6cd6fa9b3d4ee50dd963853ee6ca4f8354ecf4. Apply its editable tracks, source-range trims, preserving human overrides, timed subtitles, preview inspection and export discipline through Lumina's actual native editor. OpenFilm's HTML syntax, CLI and page-rendering contract are not Lumina tools; do not claim interoperability. Runtime reference access is unnecessary for routine editing because the relevant method is adapted here.

1. **Open and resolve assets.** Invoke actual native Video Editor creation/open with the intended canvas/project context. Reuse its saved draft across revisions. Import approved canvas video/audio assets through the native Canvas/media path or actual tool asset ports; opening an empty editor is not import success. Confirm each required file is accessible and fully ready. Record the returned media and project identifiers. Do not replace source clips with placeholders or import the whole unrelated canvas.
2. **Read, save and assemble.** Read the latest draft immediately before changes and save a supported revision/snapshot. Keep source media, user-locked tracks, overrides and unrelated edits. Use native clip instances referencing approved BGM-free prepared media with explicit source in/out, timeline start, playback rate, transforms/crop and gain; retain raw source provenance. Trim/reorder non-destructively rather than re-encoding intermediate files. Keep visuals, title/captions and audio on separately editable supported tracks; use the editor's actual compositing rules with titles above the picture. Use hard-cut picture boundaries, with no transition overlaps, duplicate spans or black gaps. Preserve approved scene order unless the user requests a change.
3. **Automatic scoring and music-driven cuts.** Follow `audio-postproduction.md`: infer fitting original/cleared final music from actual content, mood, dialogue density, story rhythm and ending; resolve/produce real ready audio through native tools unless the user explicitly excludes music or supplies a choice. No routine extra questionnaire is needed; music is part of the final preview for approval. Keep post-scope boundaries: music does not authorize unrequested stitching or captions. Inspect real waveform/playback and obtain genuine beat/downbeat/phrase/drop/ending markers; do not invent BPM. Place reveals, action accents and hard cuts on suitable markers while preserving exact dialogue, holds, complete actions and lip-sync. Adjust score phrasing/tails first; never accelerate speech or delete words for a beat. Use native choices only for substantive unresolved changes or actual missing capabilities. Do not claim analysis/clearance or native generation that did not occur.
4. **Dialogue, effects and visible sound tracks.** Keep real separately editable video, BGM, subtitle (when selected) and effects/ambience tracks, plus correct embedded or dedicated dialogue/narrator audio. Use actual supported native operations to isolate/extract retained audio; an extracted mixed soundtrack is not separate stems. Never flatten the editable draft, populate empty pretend tracks, or discard sound to imitate separation. Mute duplicate embedded sound only after its correct replacement is audible. Preserve required effects and original sync; distinguish off-screen speech from visible mouths. Duck final music under voices/essential sound with actual gain/fade controls; avoid double audio, clipping, accidental mute/solo and abrupt tails. Move linked dialogue/foley with picture during ripple edits. Adding a track alone proves neither audible output nor mouth match. Missing required separation is a native recovery blocker, not permission for silent output. Policy-blocked outputs remain governed by production-requests.md.
5. **Subtitles only when selected.** Derive captions from actual final approved speech/transcription with verified timestamps, punctuation, speaker/language and line breaks. Use native captions/text tracks or supported SRT/VTT import; never assume a specific port or format exists. Keep timed text editable and avoid duplicate burnt-in/native captions. Follow safe areas, readable contrast/size and normally one or two lines; preserve exact approved text and do not translate unless requested. If source-aligned timing exists, map to the edit using timeline_start + (source_time − source_in) / playback_rate, respecting actual transitions/linked timing. Recalculate after trims, speed, ripple or reordering, and inspect cues at boundaries. Retain transcript/source timing when only clip speed changes; do not regenerate speech to stretch it. No captions must remain on music-only spans unless approved as titles/lyrics.
6. **Preview and inspect.** Save the actual draft and show its real native playable preview, or a supported review export if a playable preview requires one. Check the whole sequence/contact-sheet equivalent plus critical transitions, first/middle/last frames, audio and caption boundaries. Confirm model/ratio, BGM-free source clips, scene/extension choice, hard cuts, shot/line coverage, order, trims, real duration, stable voice/character, music accents, complete dialogue, lip-sync, readable captions and no missing assets, gaps, duplicate spans, unintended muted/hidden tracks or extra sound. A contact sheet cannot prove audio sync; use actual playback/analysis. Distinguish checks performed from unavailable ones. Return this exact revision to the final native review card; do not claim editing is complete from a tool acknowledgment.
7. **Revise in place.** Read current draft, apply only the native-card change request, preserve unrelated human edits, retime dependent captions/audio/beat markers, save a new revision, recheck affected areas and overall continuity, then return to final review. No whole-project restart or regeneration unless the requested change genuinely requires it.
8. **Export after approval.** Export the exact user-approved current revision through native Video Editor. Use project ratio/timebase and supported output settings; prefer a broadly playable MP4 when available without inventing codec controls. Await the real export task, verify completed artifact ID, accessibility/download and actual duration/picture/audio/captions. If draft revision changed, return to review rather than exporting an unapproved revision. If export changes the appearance, re-review that changed result. Exporting, exporting subtitles separately and downloading are different operations; return the real downloadable media file/URL plus native editable draft and optional subtitle files when actually available. An editor URL, cloud draft or invented MP4 link is not the requested download. An expired link is refreshed through actual host support.

## Completion and local recovery

Normal film completion requires all current shots approved, submitted post-choice, actual native editor project for selected editing, returned final approval for its current revision, successful downloadable export with approved shot/line coverage and audio/subtitles matching scope. Every required shot's approved content is represented once unless intentional reuse was requested; multiple non-overlapping instances of one source are not duplicate content by themselves. No pending required job or unresolved blocker is marked done. User explicitly declining post-production gets clearly labeled approved source clips, and only the matching clip-delivery mode is complete.

Technical repairs preserving content continue automatically with bounded retries; policy/creative changes use native choices. Keep correct clips, voices and edits. A failure of one role/shot/export does not erase independent successes. No failure is hidden by dropping that shot or delivering a silent/incomplete movie. Deliver the approved downloadable result and any actual draft, script, table, source/credit information and subtitle assets, identifying genuine limitations without claiming unsupported tools ran.
