# Automatic important-object detection and reusable prop images

## Scope and automatic extraction

After the full script is approved, analyze that exact version together with the selected style and available supplied scene/prop references. Extract important physical objects automatically alongside the cast; do not ask the user for a prop list, manual nodes, uploads or a decision about which object to generate first. Re-scan when forming the master table/boards because a newly planned close-up can expose a need not obvious in the initial script. This is internal visual breakdown, not premature final shot-table approval.

Include an object when any of these applies:

- Its appearance is important in a close-up, insert, reveal, inspection or detailed character interaction. A single appearance can qualify.
- The SAME identifiable object recurs in meaningful shots/scenes and must keep its identity or state. A foreground action is not required.
- It carries an approved story clue, action, emotional motif, functional interaction or distinctive identity whose inconsistency would change the story.
- A background prop, furnishing, ornament or decoration is visually important, receives detail/close-up attention, or recurs as a recognizable continuity anchor. Do not exclude it just because it is in the background or no actor touches it.

Scan scene descriptions, action, object-related dialogue, framing implications and relevant visual dressing, not only nouns in spoken lines. An object mentioned but never shown need not get an image. Mere repetitions of a generic word do not prove it is the same object; resolve each physical identity from script context. Ordinary incidental clutter remains part of the scene dressing unless the importance/close-up/recurrence criteria apply. Do not generate a separate reference for every object in every background.

Use the approved content as evidence. If the script leaves a recurring set's necessary visual dressing unspecified, choose coherent minimal design defaults in the selected style and label them as production-design decisions; do not claim the script explicitly named them or invent a new story clue. Existing user-specified important props are included. A genuine contradiction preventing faithful production gets a focused native clarification; routine material/color/shape choices do not become a questionnaire.

## Prop identity and state map

Build a versioned conceptual record per distinct object, with a stable logical ID such as PROP001, name/aliases, reason for inclusion, source scene/action/line evidence, known/planned appearances and close-ups, scene placement where relevant, interaction/scale relations, identity features, permitted states, actual image/node/output IDs, ready/QC/approval versions and dependent shots. These are project records and labels, not invented native API fields or media handles.

Deduplicate the same object across appearances and reuse one master identity. Distinguish similar separate objects when the script calls for them. Lock silhouette, proportions, material/texture, color, important markings, attachments, openings and relevant wear. Record intact/broken, open/closed, filled/empty or other states only when supported by the approved action; variants link to the same object, not a new unrelated identity. A changed state does not authorize random redesign. Do not invent measured dimensions, legible text or evidence absent from supplied material; use coherent relative scale for fiction where unspecified. Documentary/evidence styles retain genuine-source requirements.

Characters remain in the cast map and ordinary props in the prop map. If a personified object is genuinely a character, preserve its canonical character identity and link its object role if needed; do not generate a conflicting second design. A prop incidentally included in a character sheet does not automatically provide a clear enough reusable object reference. Resolve whether the object itself is visible at the detail needed; create its own reference when required.

## Generate the actual prop images

Write each prop's prompt automatically from the locked script/style/design and invoke the actual native IMAGE generation route. Default to one clear landscape **16:9** reference image per important object, using the real supported ratio/dimensions and verifying output. Preserve supplied usable matching originals rather than gratuitously regenerating them. Seedance 2.5 remains the VIDEO default, not an invented image-model choice.

Keep the object large enough to inspect, fully readable with a clean/simple background, correct material/color/shape and no unrelated people or clutter. Use the most informative angle. Add a genuinely necessary alternate side/detail/state view for a later close-up or mechanism, linked to the same master; do not force all props into the CHARACTER face/costume multi-view layout. Do not present three unrelated objects as one multi-view reference. If views share a sheet, confirm their identity and use an appropriate single-view reference when the downstream tool would duplicate the object from the sheet. Do not crop rejected assets as a workaround.

For important background ornaments, preserve both object identity and their placement in relevant scene/set anchors. An isolated object reference alone cannot lock a room layout, mounting position or screen-side relationship. Use actual supplied scene images or native scene-reference generation only as needed for continuity; record stable relative locations and scale. Do not treat the isolated prop image as the whole-shot starting frame.

Use runtime-control.md's actual node/task/output and bounded synchronization rules. Reuse compatible existing nodes/ready outputs. Start with the first real required visual asset, then process all remaining required roles/props automatically, initially serially; no extra paid probe or per-object “continue”. Generation acceptance is not completion. Resolve the output and inspect identity, required detail, state, view and 16:9 dimensions. Repair failed props within existing limits, preserving correct character/voice/prop work. A missing required prop image remains a dependency blocker rather than a fictional asset ID.

## Review within the existing visual-asset gate

With required scene/set references, follow moodboard-visuals.md: refine/inspect all actual initial character/scene/prop masters and use ONE **角色／场景／道具设计确认**. The no-scene title variants below apply only when no scene masters need review; absence of characters/props does not skip required scene design or shot boards.

Generate and inspect all required character sheets AND initial important-prop references after script approval, then show their actual labeled images for a SINGLE existing visual review interaction rather than inserting a prop-list interview or one card per object. Use the actual native Question schema and keep approval version-specific:

- Characters only: **角色三视图确认** — 全部通过 / 调整指定角色 / 重新查看.
- Characters and props: **角色三视图与道具图确认** — 全部通过 / 调整指定角色或道具 / 重新查看.
- Props only: **道具参考图确认** — 全部通过 / 调整指定道具 / 重新查看.

These are applicable titles/options for the same production gate, not three consecutive questions. Fit actual schema limits, page previews without approving unseen images and capture targeted edits via real native Other/text input when needed. Do not infer approval of hidden assets. The role-only “no characters” skip does NOT skip required prop generation/review. If no required cast, scene or important-prop masters apply, record why and skip the inapplicable initial visual gate without fabricating assets; required composed shot boards still follow moodboard-visuals.md. After actual visual approval, automatically continue the existing voice/audition/table sequence.

For an already-running project or an important object first identified during table/board preparation, generate the missing reference automatically and present only the new/changed actual prop versions through a native incremental visual review before approving the affected table/producing its dependent shots. Preserve earlier approved roles and voices; do not restart the script or all visual work. No ordinary per-object confirmations are added. A material story/identity change reopens only its genuinely affected gates.

## Bind the approved reference to every relevant shot

In the master table, map each relevant close-up/recurring/background-object appearance to its stable prop ID, actual approved image/version, required state/view, placement/scale and associated scene anchor. Cross-check the approved script, visual description and planned appearances: no important object may silently lose its reference or change identity between scenes.

Connect the actual appropriate prop reference to the board/image/video operation through SUPPORTED native image/reference ports and real ready handles. A name, prompt label or logical map alone is not an attachment. Carry it to each relevant independent shot AND true extension where the actual route accepts it; do not assume the previous video preserves object identity. Respect real input-count/type limits: attach only objects relevant to that row and the most useful views, not the whole library. If a limit requires a supported scene anchor/composite, verify all necessary identities and layout survive; otherwise use native recovery rather than silently drop a crucial reference.

Never attach prop/character image links to ordinary audio execution merely for association; speech-inputs.md still governs operation-specific inputs and empty-ID prevention. Real logical asset mappings remain separate from execution dependencies.

Inspect generated boards/clips for object shape/material/markings, count, scale, hand contact, placement and state progression where relevant, including background continuity. Fix only the failing shot/asset and genuine dependents. A prop-image/version change invalidates its dependent visual approvals/tasks, not unrelated speech or scenes. A new table revision or changed prop still needs the relevant existing native review; a technically verified unchanged handle repair need not trigger whole-film reapproval. Keep the prior sound, hard-cut, extension, per-shot approval and final export rules intact.
