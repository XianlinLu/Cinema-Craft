# Deliver a canvas artifact before asking

Apply this reference at activation/resume, before a Question, and after an error. It governs drafting and recovery; the existing approvals still govern committed production and export.

## Default action and first useful canvas result

1. Read the current brief and reconcile the active canvas, saved artifacts, approvals and tasks in the project scope below. Infer reversible creative defaults from the brief. If options fit equally well, draft the strongest recommendation and record the few assumptions that matter. Do not ask for a premise, cast list, duration or direction the user already gave, or require them to approve a plan before seeing anything.
2. In the same run, write or update a real readable canvas Draft Storyboard with the first three shots (or all if fewer) and their cut cues. Use the latest script if present; otherwise derive a provisional beat sequence from the brief and applicable research. For each shot include stable scene/shot ID, estimated time, visible action and composition, continuity from the previous shot, and a hard-cut or continuous same-scene handoff. Use actual existing matching images or native draft sketches where supported and already authorized; otherwise make a concrete, editable text storyboard. Never label text, blank nodes or planned time as generated image/video, measured timing or final QC. Do not add a paid sketch probe or duplicate a current board merely to show progress.
3. Read back the saved artifact. Point to it in one concise update and continue the next ready action. If a decision matters, show the actual saved artifact first and give one native choice for that decision, with a recommended action and meaningful targeted changes. A required script/table card contains only the real artifact locator and decision controls. Offer an overview when it exists: a readable whole-film canvas shot sequence with timings and current assets; call it a playable rough cut only when a real authorized native editor preview exists. Do not invent a view switch or preempt post-production scope.
4. On resume use the most advanced valid work. If storyboard work already exists, update/reuse the current shot sequence or draft table and show what is ready and what is affected. If further downstream, advance the current eligible artifact instead of restarting the first three shots. Report only useful milestones or a concrete blocker, not a chat message for every node creation or QC pass.

## Two-turn loop breaker

- Before another clarification or confirmation, compare the current artifact and stage with the last two assistant decision turns in this project's active session. Track consecutive turns spent gathering information, proposing a plan or reconfirming it without saving a useful canvas result. A new populated artifact or a substantive saved revision with readback counts; empty nodes, duplicate cards, unchanged copies, and progress prose do not. Count semantically equivalent questions even if wording or labels change. A healthy running job, genuine unanswered required approval, or explicit pause is not a clarification loop.
- On the second such turn (intercept before issuing the repeat if possible), skip the optional question and execute the recommended reversible draft in the same run. For early work produce the basic storyboard and cut cues above; at a later stage produce the current scoped draft/overview and continue independent ready work. Persist the new artifact/version and next action. Reset the counter only after actual progress or a material new brief/scope, never after rereading the Skill or replacing a card.
- This does not imply the user accepted a direction or waived a defect. Retain required approvals for production, material creative changes and export. If a necessary approval or host capability still blocks dependent work, preserve the draft and surface the one real blocker. If canvas writing itself fails, reconcile using existing bounded recovery, then show the actual draft in chat as an explicitly unsaved fallback; it does not qualify for script/table approval. Do not loop on a failed write or pretend background execution will wake up.

## Move past a storyboard repair limit

For character sheets, use the single layout check in characters-voices.md. The exceptions here apply to storyboard composition boards. Classify each actual remaining defect against the approved story and continuity. Cosmetic differences that do not change meaning, identity, required props/actions, continuity or usable input can be disclosed on the current real board and carried into the existing table review. Record what was inspected and the limitation; do not call it corrected. Missing story-critical details, broken action/identity, unusable references or policy rejection still block the affected production path. A recurring prop detail is material if it carries a plot beat or a match between shots; do not classify it by size alone.

After the existing correction budget, stop repeating the failed repair and check for a usable existing candidate, approved reference, or simpler framing/insert that preserves the approved story. Save the best current boards plus a draft table/sequence for the full planned coverage; mark blocked rows, exact defects, and the recommended concrete fix. Keep unrelated work moving. An explicitly draft table with blocked rows is not TABLE_REVIEW_READY. Where a real equivalent board is usable without a material scope change, carry it and the disclosed note into the normal Shot Production Table Review. Otherwise ask ONE native decision with the saved alternatives, affected shot versions and tradeoff. Offer another repair only for a genuinely different supported action within the applicable budget. A confirmed creative change authorizes its scoped implementation, not a reset of the prior failed-job budget. Do not offer a generic accept/continue that implies an essential failure passed. Once the actual decision resolves the issue, execute its scope without a second confirmation of the same decision; the final table/video gates still apply.

## Recover a Question submission separately from media

An internal-error toast after Submit proves neither that the response was recorded nor that it was lost. Use supported read-only state for the same card, artifact version and session, with the existing bounded reconciliation allowance (at most three extra reads per unresolved episode). If the correct response is recorded, consume it once and execute immediately; preserve an actual pause. If nonreceipt is authoritative and the card is usable again, direct the user to that same card once. If receipt is unknown, the card is broken or the allowance is exhausted, retain one pending checkpoint and the saved draft, continue independent work, and report the specific blocker once. Never replay the user's click, infer approval from a highlighted choice, issue another card on the same failing route, or reset the image repair budget because the card failed.

## Keep session context separate

- On activation/resume scope mutable state by actual project, canvas and agent session where exposed. Carry the current brief revision, task type, project language, selected style/source, prompt-template revision, current artifact IDs, approvals, pending card and breaker counts in that scope. Use actual host handles and supported persistence, not guessed API fields or a title match.
- Build each prompt from the active brief and current approved artifacts. Reuse only immutable method/style reference text across sessions. Validate job type, mode, source versions, language and scope before writing/dispatch; rebuild mismatched prompts from current state. Never import another session's cast, scene, script draft, pending approval, retry budget or template filled with another project's data. Exclude mismatched state from the active context without deleting other projects, tasks or history.
- For an explicit resume in a new session, reconcile the same project's actual artifacts and authoritative approvals before transferring the necessary checkpoint; do not transfer stale cards or assume old responses apply. If current ownership or intent is genuinely ambiguous, withhold only the affected action and use one focused native decision after safe independent work. Do not claim this Skill clears or partitions Lumina's backend prompt cache; it scopes the context and bindings it controls.
