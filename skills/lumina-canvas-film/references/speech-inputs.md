# Native audio input preparation and empty-content recovery

## Scope and observed evidence

Read this before EVERY audition, exact shot-speech, music or sound-effect audio submission and when its native input resolution fails. The user's repeated BALLMAudio response contains `GenInputsFromPipeline ... validate audit content 0: content id is empty` and code 15000. This is evidence of an empty content identifier during input/audit validation, not proof that spoken text is empty, a character picture is missing, concurrency is excessive, copyright was rejected or a particular model is unavailable. The message does not reveal the missing input type. Numeric 15000 alone is not a universal error definition. Nested request/log IDs and different timestamps should be recorded without assuming they prove stale assets, a prior user's task, or the same underlying failure.

Use actual exposed schemas, node inputs, producer status, registration results and error details. Do not invent an internal audit inspection or content-registration API. Skill text can reduce invalid submissions and repair accessible inputs; it cannot intercept Lumina's own modal UI or guarantee a working internal content service. Closing a popup is not a repair.

## Prepare a minimal operation-specific input set

First determine the REAL audio operation and its required inputs. An audio wrapper name does not specify whether it performs speech synthesis, original voice design, voice-reference/clone processing, music or effects. Preserve approved voice choices and language/performance. For character auditions and later character speech, the user explicitly requires the approved character image as a real generation input: apply the image-binding contract below. This does not authorize real-person voice cloning.

| Real supported operation | Resolve according to its actual schema |
|---|---|
| Character-image-conditioned audition or speech | Approved ready character image connected to the actual native image-compatible audio input, selected profile and exact text; later speech also retains the locked approved voice/audio identity |
| Existing-voice speech | Exact nonblank spoken text plus a compatible real voice/settings handle; no picture/audio reference unless this operation requires or intentionally uses it |
| Original voice design / text-described speech | Actual supported descriptive profile/settings and nonblank test/script text; no requirement for the audition's own FUTURE voice/audio output |
| Reference-conditioned speech or explicitly authorized cloning | A genuinely required existing ready reference/voice of the correct type and ownership; never create an empty reference to enter this mode |
| Music or effects | Original production brief and actual required controls/assets for that route; do not inherit role-picture or future voice inputs accidentally |

The table is conceptual, not a provider argument list. If the desired operation is absent, preserve the request and use the existing native capability-recovery gate; do not substitute another voice/engine, clone mode or content scope silently. For image-backed character speech, metadata, labels and non-input relations alone are insufficient. Inspect the native port semantics and resolved reference: a decorative edge or typed @name does not supply an image to generation. Keep the required image input and valid voice inputs intact.

Create one immutable input/job record per role/line/cue and version. Store source script/profile, exact text/brief, operation, required inputs, allowed intentional optional inputs, saved node configuration and request fingerprint. Do not share or append to one mutable batch reference list. Do not attach the whole canvas or copy an old node with unresolved inherited reference ports. Reuse a valid existing node, but inspect its actual saved inputs rather than assuming a visible caption reflects its payload.

## Approved character image must be an actual audio input

Keep the existing Voice Preferences and Voice Audition Review cards completely unchanged: same titles, questions, profile choices, recommendations, custom-input behavior and approval semantics, with the existing project-language adaptation. Add no image-selection or connection-confirmation questionnaire. Resolve the image automatically from the previously approved role design.

For EVERY audition and subsequent newly generated dialogue, character narration, dubbing, correction or multipart speech segment of an image-backed role:

1. Resolve the target role's own USER_APPROVED character sheet, its exact image version, real canvas node and ready image asset. Do not use a relative's anchor, another cast member, an unapproved replacement, an empty node or a planned image. Off-screen speech by a depicted role uses that same role's image. A narrator with no depicted character keeps the established narrator route; do not invent a portrait or borrow another role's image.
2. Discover an actual native audio operation that accepts the image reference and the selected voice requirements. Connect the approved character-image output to that audio node's real supported image/reference input ON THE CANVAS. Use the exact native parameter names, port types and returned media handles. Keep the original approved sheet as the visible source; if a compatible portrait crop is technically required and supported, create a real faithful derivative, preserve the visible sheet → derivative → audio chain and record its lineage. Do not synthesize a new face just for audio.
3. Save and read back BOTH the graph edge and the audio node's resolved image input before execution. Verify the edge starts at the intended approved image/version, ends at the intended role's audio input and resolves to accessible ready image content. A nearby image, text description, role label, manifest entry, decorative connection or prompt mention alone does not meet this requirement. Record only evidence actually exposed by the host; never claim hidden model internals were inspected.
4. For the INITIAL audition only, ground the voice-design prompt in the attached character and approved characterization, while retaining the user's selected timbre, pitch, language/accent, pace and performance. The image is a creative identity reference, not evidence of a person's actual voice, nationality or accent. The existing voice choice governs these qualities; do not replace it based on appearance.
5. After audition approval, lock role ID + approved image node/asset/version + selected profile + approved voice/audio handle/version. Every later character-speech node must have its own real connection to this same approved image source and retain the locked voice/reference through supported native inputs. Reusing a voice handle alone does not satisfy the image connection requirement. Do not redesign or randomize the voice for each line. Preserve exact approved script text and distinguish audition copy from production speech.

If no exposed native route accepts both the required image and voice constraints, hold only dependent speech jobs and use the existing native capability-recovery flow. Never invent an image-to-audio field, connect an image to an audio-only port, silently fall back to text-only speech, or claim visual conditioning from a decorative edge. A supported voice-reference image route must be discovered, not assumed from the BALLMAudio wrapper name.

An empty-content repair must resolve/rebind the required image's actual ready handle, not remove it as an optional input. Keep the bounded repair/acceptance rules below. A technical rebind preserving the image and voice versions does not repeat creative approval. A newly approved replacement image updates only this role's affected input records and future/repaired audio; do not automatically regenerate already approved good audio or unrelated cast. Never relabel old audio as generated from a new image. A changed voice still needs the existing voice approval.

## Approved audition → actual character speech

After the existing Voice Audition Review returns approval, automatically create or reuse each required production-speech node for that speaker. Keep the existing voice cards unchanged. Resolve the exact USER_APPROVED audition node, audio output and version, not the newest unapproved candidate or another role's sample. No extra audition or routine confirmation is needed.

Connect the approved audition's actual audio output ON THE CANVAS to every corresponding production-speech node's supported native voice-reference input. Preserve the required approved character-image connection as a separate input under the previous section. Use actual native ports, parameter names and returned ready handles. A stored voice ID, typed reference name, prompt sentence, manifest association or decorative line alone does not replace this audio-source edge. Read back the saved edge and resolved audio asset, and verify the source role/version before submission. Record both image and audition lineage on the same speech job. If the real input limit requires a shorter reference, create a genuine compliant excerpt from that approved audition with a visible audition → excerpt → speech chain; never use a fabricated clip or another voice. Prefer the direct audition → speech edge when supported. Apply actual audio-reference limits; do not change the approved source sample itself.

### Minimal production-speech prompt

Use only the localized equivalent of:

> Using this reference voice, generate: "{exact approved script line}"

Replace the placeholder with this speaker's actual approved script wording, preserving punctuation and the requested spoken language. For a Chinese interface, the lead-in means: reference this voice and generate the quoted line. Do not emit placeholders, audition test copy, character labels, stage directions or invented words as spoken text. Do not add descriptive prose about timbre, gender, age, accent, emotion, speed, vocal texture or delivery to the production-speech prompt. Those voice-design details belong to the already approved audition; inherit its voice through the real connected reference. Keep role IDs, image bindings, source versions, timing and operational metadata outside the prompt, in actual native fields or the project ledger. This constraint concerns formal speech generation, not the initial audition prompt or the structured video prompt.

If the native node separates an instruction/prompt field from a spoken-text field, put the brief reference instruction only in its supported instruction field and put ONLY the exact line in spoken text. If it provides one instruction-style prompt field, use the short template above. Never send the instruction wrapper to a literal TTS text field and let it be read aloud. Do not invent fields to force a particular schema. Reuse approved voice settings only through actual supported controls; do not restate them as extra prompt prose.

Apply this to new lines, multipart line outputs and targeted dubbing repairs, including narration using its own approved audition. Check actual output for exact words and matching voice without audible instruction text. Changed audition selection invalidates only dependent pending inputs and affected voice-dependent outputs; preserve unrelated successes and obtain existing voice approval for a genuinely new voice. If the native route cannot consume the required image and audition reference together, use the existing capability recovery instead of dropping either reference, recreating the voice from adjectives or pretending a visual edge is conditioning. Empty-content repair must resolve or rebind the approved audition input, never remove it to force submission.

## INPUTS_READY barrier before execute

Do non-generating preparation first. A ready-looking node, successful save call or placeholder is not evidence of a ready content reference.

1. **Text/profile:** resolve actual script text or audition copy, trim only accidental boundary whitespace and require meaningful nonblank content. A file name, variable token, “see script above” or placeholder is not spoken text. Preserve exact approved lines, owner/language and requested performance. If the actual route accepts inline text, use that documented path. If it requires registered text content instead, materialize/register it through the REAL supported operation and retain its returned ready handle. Do not invent registration fields or require registration when inline text is sufficient.
2. **Each required reference:** obtain its real upstream output and the correct route-compatible identifier through supported resolution. Check producer task success, accessible nonempty media/text, project/session access, intended owner/version and any exposed upload/registration/readiness state. A task ID, canvas node ID, voice ID, URL, media asset ID and internal content ID are NOT interchangeable. Nonblank syntax alone is not validation; a URL is not a registered content ID merely because it opens in a browser.
3. **Optional inputs:** omit unintended empty/whitespace/null/unresolved reference items using the actual schema. If an empty collection is required and valid, use its declared form; do not fabricate nonempty dummy items. Remove only a diagnosed erroneous optional execution binding through actual native controls, preserving the source image and required image-to-audio execution connection and, for production speech, the approved audition-to-speech connection. An image-backed role's approved image is mandatory even when the generic API calls the port optional. Do not disconnect valid required input or replace it with a placeholder to force submission.
4. **Save and resolve:** save the actual node's intended operation/text/settings/bindings through supported controls and read back current inputs where available. Reconcile pending registration or shared-canvas changes under runtime-control.md before dispatch. A required reference that is uploading/processing is not ready; query its existing producer/registration with actual host continuation, not repeated audio-generation calls. A terminal empty input is a repair/blocker, not an endless pending wait.
5. **Final input check:** compare the concrete input set with the immutable role/line record and confirm no missing required input, no stale cross-role reference, no future-self/circular dependency and no unresolved optional execution item. Use a genuine native non-generating validator/preview if offered. Never execute an audio-generation job as a probe for readiness. If the wrapper hides compiled inputs, validate all observable supplied fields and record that internal resolution is unverified; do not claim access to hidden internals or invent a validator. Unresolved required external inputs cannot pass this barrier.

Mark INPUTS_READY only for the current saved input version and actual supported route. Changed input/profile/reference versions invalidate that readiness. A local fingerprint helps locate prior dispatch; it is not provider idempotency. Resolve every previous attempt's acceptance through runtime-control.md before any retry, even if the current error occurs during input validation.

## Submit the actual deliverables automatically

Generate the first REAL requested audition end to end; no extra paid diagnostic sample. Default the remaining ready-role jobs to a serial automatic queue, with no user “continue” between roles. Keep distinct operation-specific bindings for audition master, exact film lines, music and effects. Any concurrency must respect actual supported quotas and healthy resolved inputs; serial ordering alone does not fix an empty ID.

On success, resolve and play the actual output; verify text/owner, voice, measured duration and clean sound before GENERATED. Submit/accepted/Completed/tool-toast states do not establish output success. Audition masters still target 20–30 seconds; exact shot speech keeps its real wording/duration, and music/effects follow their own plan. For image-backed roles, GENERATED also requires recorded evidence of the approved image-to-audio binding used by that job; narration with no depicted role, music and effects do not inherit invented character-image inputs.

## Automatic repair after an empty-content error

1. Save exact outer and nested error/request/log IDs, operation, node, role/line, input version, dependency map and current acceptance evidence. Query a known accepted task; unknown acceptance forbids duplicate paid submission. Repeated notifications of the same task/log are one failure, not additional attempts.
2. Inspect the actual failed node and submitted/saved inputs where exposed. The phrase `content 0` identifies an indexed validation item, not necessarily the first image, voice or text in the user's mental list. Resolve its type/producer from actual tool evidence; do not guess it from a screenshot.
3. Apply ONE evidence-backed native repair: resolve a completed producer's correct output; finish exposed pending upload/registration; rebind a stale required handle from a verified ready source; supply the actual missing text through the supported inline/registered route; or omit a diagnosed empty optional item/incorrect execution edge. Only for work without required image conditioning may an accidentally reference-dependent operation switch to a supported no-reference route that genuinely matches the original request before approval. Character auditions and dubbing must retain their required approved image input; production speech also retains the approved audition audio input. Preserve approved voice identity; any material voice/engine/content change requires the relevant native decision.
4. Read back/revalidate all observable required inputs and record the before/after difference. Retry the SAME logical audio job only AFTER an observed repair and resolved acceptance, at most once for that repair, within the existing total maximum TWO distinct technical-correction retries. Do not call the unchanged payload again, reset its budget by creating another node, or cycle through models/routes hoping the error disappears. A scheduled wait alone or a new node name is not an input repair.
5. If the binding cannot be edited and evidence shows the node itself is unusable, a supported replacement of ONLY that audio node may be necessary after task acceptance is resolved. Rebuild its verified minimal inputs; keep original role images and correct audio. Replacement consumes the same logical job/repair budget, and must not clone the broken input graph. It is not a routine first response.
6. If observable inputs are valid but the wrapper still reports an empty internal ID, do not fabricate a cause or continue blind retries. Save an internal-resolution blocker and stop that faulty route's new submissions. Prepare independent assets without using that failing path, preserve successes, and use one genuine native recovery card only at the actual dependency barrier. Missing internal registration/status capability may require platform investigation. Do not promise automatic repair of an inaccessible backend.

## Prevent a batch of repeated popups

When one shared audio route/input-template fails with unresolved empty content, hold NOT-YET-SUBMITTED jobs using that same unresolved path. Do not execute each remaining character to discover the same error, or run the whole canvas including known-invalid nodes. Already accepted jobs are still reconciled; genuinely independent ready routes can proceed if the shared canvas is healthy. Release the held queue only after an observed shared-input repair and the first repaired real deliverable succeeds, or after each item is proven unaffected by the diagnosed fault. Never classify jobs as independent merely because their role names differ.

Expose normal progress without asking for routine technical approval. After automatic technical repair, resume the current real audition/line and remaining queue; keep existing creative approvals and all later native review gates. A persistent blocker gets the existing native recovery interface with only actual supported actions, preserving a readable support summary; do not contact support automatically. If the host supplies non-modal status/error handling, use its actual supported capability; never invent `silent`/`suppress_errors` flags or hide a failed stage. Lumina may still display the first backend error before the agent receives it. Reducing bad calls and preventing repeated batch failures is the achievable Skill change, not a guarantee that all platform popups disappear.

This recovery does not alter policy-rejection handling or permit extracting blocked results. It also does not authorize silent film shots: all intended speech/effects must be audible under audio-postproduction.md before shot confirmation, regardless of how audio inputs were prepared.
