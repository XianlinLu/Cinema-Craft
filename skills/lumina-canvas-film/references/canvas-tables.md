## Master-table column contract

Apply language-policy.md to ALL visible titles, gate labels, headers and cells: canonical English names below are templates to localize, not a fixed interface locale. Save/read back EVERY shot on canvas with the nine localized columns in language-policy.md, in order. Keep one concrete Visual Description using production-requests.md; no duplicate description, translation column or new questionnaire. Stable scene/shot IDs retain the linked asset/dependency/status ledger.

- **Start Time / End Time:** absolute positions in the approved production plan, starting at 00:00:00. Use one consistent HH:MM:SS format (or HH:MM:SS.mmm when real subsecond precision is needed); distinguish these from local shot cues starting at 0. End is exclusive, duration = end − start > 0, and each shot begins at the preceding end across scene boundaries. Derive boundaries cumulatively after measured speech/action allocation; follow the existing integer prompt-timing rules. Show total runtime. No overlap for hard cuts, independently rounded gaps, or resetting the film clock for each scene. Label planned times as planned; actual generated duration/source in/out and later editor time are separate measured/versioned records. Post-production trims update the edit map rather than silently rewriting an approved production table.
- **Dialogue:** exact approved wording with speaker/line identity and an explicit Dialogue, Off-screen dialogue or Narration label as applicable. No spoken content is **No dialogue**, not an invented line. Keep off-screen/narrator ownership and per-shot speaker rules; show exact line-span mapping when splitting speech, and retain real approved audio IDs/durations in shot detail. Sound effects and BGM are not dialogue.
- **Shot Size:** choose the framing needed by the action/story, e.g. Extreme wide shot, Wide shot, Full shot, Medium shot, Medium close-up, Close-up or Extreme close-up. Name what is framed when useful; do not confuse shot size with lens length, camera movement or subject size. A genuine within-shot framing change states start → end and must agree with the planned camera path. Do not introduce contradictory setups merely to fill this cell.
- **Focal Length Rationale:** provide an intentional lens proposal plus a brief reason tied to subject distance, spatial relationship and the selected style. For physical/virtual perspective cameras, label a chosen value or justified range in **35 mm full-frame-equivalent mm**, e.g. a wider spatial view versus a compressed detail; do not claim a value was measured or guaranteed by a generative model. Shot size alone does not determine focal length: reconcile position/distance, framing, perspective and board. Avoid switching focal length merely for variety or contradicting continuous extension. For flat/orthographic graphics without a perspective lens, explicitly write **Not applicable (2D / orthographic; describe composition scale)** rather than fabricate optical metadata. Send only real supported parameters; a lens direction in prompt text is not an unexposed API argument or proof of optical execution.
- **Background Music:** write **Post-production music: ...** with the story/style function, mood, instrumentation/texture, intended cue range, entry/exit and continuity/ducking as relevant; or **No music** for an explicit no-score choice or intentional scored silence. A shared scene/whole-film cue keeps one stable cue ID across relevant shots, not a new unrelated song per row. Before real score creation, mark planned/pending music and beat positions honestly; do not invent an asset ID, BPM or analyzed beat grid. Exact musical markers follow actual selected/generated audio later. This column is a FINAL native-editor scoring plan, never an instruction to generate model BGM inside each shot. Respect user music choices and original/cleared sources; final selection and mix appear in the existing final preview approval.
- **Sound Effects:** specify required action-synchronous effects and ambience with their source/event, local cue or interval, continuity and rough level/placement when relevant; distinguish designed/planned cues from real prepared media. Use **No effects / Intentional silence** only when supported by the scene; no dialogue does not imply no ambience. Effects/ambience and intended human speech must remain audible in the prepared shot before review, even though BGM is deferred. Real effect IDs/versions and native editor track placement stay traceable in shot detail. Do not assume or claim stems/separation or sounds not actually produced.

Automatically check all rows before presenting the existing native approval: all required visible columns populated; single description; exact speech fits measured time; contiguous positive project intervals and correct total; shot size/lens/camera/board consistent; BGM stays deferred; effects and speech have an actual viable production route. Repair only deficient planning fields without restarting correct assets or asking routine lens/music questionnaires. Substantive changes to approved story, voice, visuals or explicit user choices use the relevant existing native revision gate. Carry approved framing/lens intent and sound cues into boards, native requests and the editor cue map; verify actual output rather than infer success from the table.

## Runtime routing and actual segment boundaries

Use the approved final runtime, story beats, measured speech and actual native duration limits. Preserve composition-board and shot-row IDs independently from generation-unit IDs. One request can cover several approved timed beats. Map every generated span back to its table rows and record actual duration. Do not interpret the number of rows as the number of video jobs.

- **30 seconds or less.** Prefer one supported Seedance 2.5 request for the full film with a timed sequence and approved reference assets. Honor the real endpoint duration range. If that runtime or required mode is unavailable, use the existing native recovery choice for a supported route. Do not silently split or switch model.
- **Over 30 seconds.** Follow the observed initial-segment → actual ending analysis → next-segment extension cycle. Select a first segment and subsequent durations at motivated story/action boundaries within the native range, keeping the approved total runtime. A first segment may be shorter than 30 seconds. The earlier fixed first-30-seconds rule is superseded for this route. Keep an explicitly user-selected 30-second-first plan when it is supported. Do not copy the reference project's segment lengths or let the sum grow beyond the approved duration.
- **Extension eligibility.** Normal continuous action must preserve compatible scene/time, identities, wardrobe, spatial layout, camera direction and lighting. An explicitly approved scripted continuous visual bridge may connect scenes only if that bridge is recorded in the table and the actual ending supports its start. A shared theme, generic scene change or source image does not establish continuity. Independent scenes, time jumps and unapproved bridges use independent generation and hard cuts. Do not invent a bridge to force extension.
- **One successor per chain.** Submit only the next eligible continuation after its selected predecessor has finished, passed necessary technical/audio checks and supplied an observed ending. Independent scenes may run under actual host quotas. Do not pre-submit later chain members against guessed future assets. A genuinely revised predecessor invalidates only its dependent descendants. Save alternative candidates separately and link the chosen version before continuing.
- **Duration and assembly.** Distinguish newly requested duration, returned source-inclusive duration and final edited coverage. Start the extension's local time at zero and record its absolute project offset separately. Remove a returned repeated prefix exactly once when assembling. If the endpoint needs a shorter source, use a supported real tail extract, record its offset and inspect its ending. If it returns only new footage, keep it once without subtracting the predecessor again. Preserve complete approved speech/action and the final runtime budget.

## Inspect the real ending before continuation

After the accepted task has a released, playable result, inspect approximately the final **1.5 seconds**, or the available tail for a shorter clip, through actual native playback/frame or video-analysis capabilities. Reuse a sufficient existing analysis for the same clip/version. Save a concise ending note on the canvas and bind it to the exact source asset/version.

Record the visible ending frame, subject/prop positions and states, camera orientation and residual motion, light/palette, frame-filling or occluding shapes, and observed remaining speech/effects/ambience. Keep measured/observed facts separate from proposed next action. A single frame supplies visual evidence only. Label unverified sound or motion as unknown and obtain the required evidence before relying on it. Do not treat an analysis model's implied music, invented object or suggested new event as an observed fact.

Then derive a short continuation brief from the approved next beats and that ending. Preserve the actual starting pose/composition and complete any unfinished approved action. Reject analyzer suggestions that add unapproved dialogue, music, genre, text, props or plot. Normal framing variation can be absorbed in the next opening without creative reapproval. If the observed result makes the approved next beat impossible, perform a bounded targeted repair or use one native revision decision for the material change. This focused boundary check is not a repeated subjective quality contest.

## Structured video prompt contract

Write every actual prompt in the resolved project language, retaining approved dialogue/on-screen wording in its requested language and real native mentions. The headings below are canonical English templates and must be localized before display. Use the same section order for first generation, independent segments and continuations. Ground the prose in approved table rows and observed assets. Never copy the reference room's story, text, characters, brands, effects-only sound choice or repeated requests to type continue.

1. **Task.** Identify the current segment's story purpose, initial/independent/extension operation, exact new duration and covered row IDs. For a real extension, begin the task with the localized equivalent of “Continue [actual predecessor video mention] for [new duration].” Bind the real source through the native video port and supported mention mechanism. A typed name or placeholder cannot substitute for the connection. State the approved output language and exact permitted on-screen text when applicable.
2. **Continuation start.** Include this section only for an extension. Describe the inspected source ending, camera/subject/prop state, residual movement, light and audible tail. Explain the physical starting state for the first new beat. Use the actual result even if the prior prompt's hoped-for ending differed. For first/independent generation, establish its start from the approved board/assets in Overall style.
3. **Overall style.** State the selected visual grammar, scene/time/light, composition, identity/wardrobe/prop anchors and camera presentation. Include required 720p and approved ratio as descriptive constraints in addition to real node settings. Resolve each reference's role, such as identity, costume, setting or composition, using approved ready inputs within actual limits. Avoid contradictory camera directions or copied demonstration aesthetics.
4. **Timeline and visuals.** Cover the exact new duration with positive contiguous local intervals. For EACH interval write start/end time, concrete visual description, shot size, focal-length judgment and one compatible camera path. Describe ordered action, body language, gaze, spatial interaction and observable resulting state. Add exact speaker-labelled dialogue/narration only when approved, including voice/audio mapping and fit. Include action-synchronous effects/ambience cues where needed. Lens values are reasoned creative directions, never invented native fields or measured optical facts. Record corresponding absolute project times in the existing nine-column table.
5. **Sound.** State the actual approved mix of dialogue, narration, nonverbal reactions, effects and ambience with exact source/voice relationships. Preserve intended human speech and effects in playable footage. Exclude generated background music for this workflow, adding final score in the native editor. Effects-only applies only to an approved effects-only passage. Never copy a reference's no-speech instruction into a speaking shot or use global mute as music removal.
6. **Ending state and constraints.** Specify one concrete finish and, where needed, the next continuity anchor. State only relevant exclusions, exact on-screen text rules and identity/prop invariants. If the approved action has multiple phases, write them in order with distinct observable endpoints. Avoid alternatives such as “object A or B” or leaving the ending to the model. Keep normal scene boundaries as hard cuts. A scripted bridge requires explicit approval and remains distinct from adding automatic editor transitions.

Skeleton for the compiled prompt (replace every placeholder from this project before saving or executing):

```text
[Task]
[Initial/independent generation purpose and exact duration, OR continue the actual connected predecessor for the exact new duration. Approved language and permitted text.]

[Continuation start — extension only]
[Observed final state, ongoing motion, camera direction, lighting and verified sound tail.]

[Overall style]
[Approved style, scene, composition, identities and reference roles. 720p and approved aspect ratio.]

[Timeline and visuals]
[0–t1 seconds] [Visual event and resulting state. Shot size. Focal-length rationale. Camera path. Exact speech if present. Required effects.]
[t1–t2 seconds] [Next approved beat using the same fields.]
[...last interval ends at the exact new duration.]

[Sound]
[Approved voices, effects and ambience with actual bindings. No generated background music.]

[Ending state and constraints]
[Single observable finish, approved next-segment anchor if needed, exact text and relevant invariants.]
```

The skeleton is instruction text, not a payload. Compile it to complete prose with real timing and bindings. Preserve the existing visible nine-column table and its review gate. Store the compiled request and ending note as related canvas artifacts instead of adding duplicate table columns or placing production text inside Question.
