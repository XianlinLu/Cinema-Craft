# Canvas shot production tables

Read `language-policy.md` before rendering any title, header, cell, note or decision. The English names here are canonical templates, never fixed foreign-language UI labels.

## Master-table column contract

Apply language-policy.md to ALL visible titles, gate labels, headers and cells: canonical English names below are templates to localize, not a fixed interface locale. Save/read back EVERY shot on canvas with the nine localized columns in language-policy.md, in order. Keep one concrete Visual Description using production-requests.md; no duplicate description, translation column or new questionnaire. Stable scene/shot IDs retain the linked asset/dependency/status ledger.

- **Start Time / End Time:** absolute positions in the approved production plan, starting at 00:00:00. Use one consistent HH:MM:SS format (or HH:MM:SS.mmm when real subsecond precision is needed); distinguish these from local shot cues starting at 0. End is exclusive, duration = end − start > 0, and each shot begins at the preceding end across scene boundaries. Derive boundaries cumulatively after measured speech/action allocation; follow the existing integer prompt-timing rules. Show total runtime. No overlap for hard cuts, independently rounded gaps, or resetting the film clock for each scene. Label planned times as planned; actual generated duration/source in/out and later editor time are separate measured/versioned records. Post-production trims update the edit map rather than silently rewriting an approved production table.
- **Dialogue:** exact approved wording with speaker/line identity and an explicit Dialogue, Off-screen dialogue or Narration label as applicable. No spoken content is **No dialogue**, not an invented line. Keep off-screen/narrator ownership and per-shot speaker rules; show exact line-span mapping when splitting speech, and retain real approved audio IDs/durations in shot detail. Sound effects and BGM are not dialogue.
- **Shot Size:** choose the framing needed by the action/story, e.g. Extreme wide shot, Wide shot, Full shot, Medium shot, Medium close-up, Close-up or Extreme close-up. Name what is framed when useful; do not confuse shot size with lens length, camera movement or subject size. A genuine within-shot framing change states start → end and must agree with the planned camera path. Do not introduce contradictory setups merely to fill this cell.
- **Focal Length Rationale:** provide an intentional lens proposal plus a brief reason tied to subject distance, spatial relationship and the selected style. For physical/virtual perspective cameras, label a chosen value or justified range in **35 mm full-frame-equivalent mm**, e.g. a wider spatial view versus a compressed detail; do not claim a value was measured or guaranteed by a generative model. Shot size alone does not determine focal length: reconcile position/distance, framing, perspective and board. Avoid switching focal length merely for variety or contradicting continuous extension. For flat/orthographic graphics without a perspective lens, explicitly write **Not applicable (2D / orthographic; describe composition scale)** rather than fabricate optical metadata. Send only real supported parameters; a lens direction in prompt text is not an unexposed API argument or proof of optical execution.
- **Background Music:** write **Post-production music: ...** with the story/style function, mood, instrumentation/texture, intended cue range, entry/exit and continuity/ducking as relevant; or **No music** for an explicit no-score choice or intentional scored silence. A shared scene/whole-film cue keeps one stable cue ID across relevant shots, not a new unrelated song per row. Before real score creation, mark planned/pending music and beat positions honestly; do not invent an asset ID, BPM or analyzed beat grid. Exact musical markers follow actual selected/generated audio later. This column is a FINAL native-editor scoring plan, never an instruction to generate model BGM inside each shot. Respect user music choices and original/cleared sources; final selection and mix appear in the existing final preview approval.
- **Sound Effects:** specify required action-synchronous effects and ambience with their source/event, local cue or interval, continuity and rough level/placement when relevant; distinguish designed/planned cues from real prepared media. Use **No effects / Intentional silence** only when supported by the scene; no dialogue does not imply no ambience. Effects/ambience and intended human speech must remain audible in the prepared shot before review, even though BGM is deferred. Real effect IDs/versions and native editor track placement stay traceable in shot detail. Do not assume or claim stems/separation or sounds not actually produced.

Automatically check all rows before presenting the existing native approval: all required visible columns populated; single description; exact speech fits measured time; contiguous positive project intervals and correct total; shot size/lens/camera/board consistent; BGM stays deferred; effects and speech have an actual viable production route. Repair only deficient planning fields without restarting correct assets or asking routine lens/music questionnaires. Substantive changes to approved story, voice, visuals or explicit user choices use the relevant existing native revision gate. Carry approved framing/lens intent and sound cues into boards, native requests and the editor cue map; verify actual output rather than infer success from the table.

## Canvas review: save the artifact, then ask

The COMPLETE Shot Production Table must be saved directly ON CANVAS, just like the full script; Question collects decisions only. Preserve the column/timing contract above, production-requests.md's actual rows, measured speech, current real boards and version-specific approval prerequisites.

1. Discover actual native canvas table/document/text create, update and read capabilities. Automatically create or reuse this project's logical table artifact, titled with the film title, Shot Production Table and current version in the project language. Prefer a real table if supported; otherwise use a genuinely readable document/text table. Markdown only in Question/chat, incomplete table screenshots and empty nodes are not saved canvas delivery. Invent no tools, node types or parameters.
2. Save every scene and planned shot with all nine columns, exact complete dialogue, concrete visuals and cumulative film times. A provisional shot script cannot stand in for the final measured table. If actual node capacity requires pagination, split by scene/contiguous shot ranges, repeat the same localized headers on every page, provide an ordered index/version and verify complete coverage with each shot exactly once. Do not omit rows, truncate cells or move remaining rows into cards.
3. Wait for actual save completion and read back ALL pages/rows/columns. Verify shot IDs, count/coverage, nine headers, full body, language and final time. Show every current real refined-or-inspected-pass board and speech preview ON CANVAS, linked to the same shot/asset versions. Persist actual table/document handles, page order, current version, completeness/readback evidence and corresponding image/audio version set. Node creation alone does not prove complete readable content or review readiness.
4. Only then issue the native Shot Production Table Review, e.g. 'Review the canvas Shot Production Table v3 for [film title] and its storyboards. Do you approve?' Localize the entire authored card and locate/reference the real artifacts only as actually supported. Keep title, question, descriptions and options concise: Approve and generate all shots / Revise a shot or image / View table and storyboards again, plus actual native text/Other where supported. NEVER put the table body, row descriptions or cell values in any card field. A locator is not a replacement for the canvas body. View again locates the existing current table/images; it neither moves them into a card nor grants approval.
5. Collect specific shot/field and requested changes inside native text/Other. Update the SAME logical canvas table and affected images/audio, read back the complete current version and issue a concise new review. Preserve unrelated correct assets and valid approvals; stale cards cannot approve changed table/board versions. A faithful relocation or display-only translation does not itself require creative reapproval. Once the actual current table and related images/audio are approved, submit authorized ready video jobs automatically without another 'continue' gate.
6. If saving fails or acceptance is unknown, retain the full plan and existing handles. Use runtime-control.md's bounded recovery to reconcile original nodes/save tasks and reuse successful writes; avoid duplicate nodes. Missing actual write/read capability or incomplete readback BLOCKS table review and dependent video production. Report the true blocker through native recovery; never substitute cards/chat, claim an unsaved table is saved, or fabricate handles. Continue only authorized work independent of this barrier.

These handles, states and evidence are conceptual durable records, not new API fields or enums. This placement contract relaxes no production or approval prerequisite.

## Seedance 2.5 duration routing and extension prompt

Choose from the approved final runtime and current native Seedance 2.5 capabilities. Keep composition boards and timeline beat rows as planning inputs. Retain their stable IDs and map each actual output to its covered beats. Inspect all beats in the single output before declaring it ready. One beat row does not equal one video job. Consult the public 30-second generation and extension guide, then validate actual Lumina modes, request and source durations, asset limits and accepted ratio values. https://docs.volcengine.com/docs/ark/seedance-2-5

- **30 seconds or less.** Use one native Seedance 2.5 generation for the full intended duration, with a single timed prompt covering the approved sequence. Attach the selected approved keyframes and assets that fit the native limits. Avoid per-shot video calls. Use supported native duration and trim only planned spare footage if the exact target is below the available minimum. If the route cannot fit the story in a single job, surface one native choice for a supported alternative.
- **Over 30 seconds.** Generate the first 30 seconds in one job where supported. After it is ready and inspected, bind its real video output to a native extension job for the remainder. Chain further eligible extensions within the host limits if needed. If the combined output exceeds the source duration limit, use an actual supported tail extract that retains the continuous boundary and binds as the next predecessor. Request only the new duration for extension, carry the correct identity and audio references, inherit the source ratio as required, and keep project time separate from local time. Trim repeated source prefixes once. When the approved story changes scene at the boundary or the tool cannot support a real extension, keep the successful footage and offer a supported segment-and-edit route through a native choice if it changes the requested route. Never pass external inspiration footage as the predecessor.

Open a real extension prompt with “Continue @video for [new duration].” Localize the opener to the project language, using “Continue” in English and the equivalent of “extend this video” in Chinese. Replace @video with the actual supported mention connected to the predecessor asset. Then describe camera presentation. For each timed beat supply **start and end time, visual description, dialogue when present, shot size, focal-length judgment**. Keep approved dialogue exact and identify its speaker. In the request use contiguous local intervals starting at zero, and retain corresponding absolute times in the project table. Reserve speech and action holds, handle a short remainder within the native minimum without cutting required content, and keep BGM out of generation.
